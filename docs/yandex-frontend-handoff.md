# Завершение регистрации через Яндекс: передача фронтенду

## Сценарий
Кнопка Яндекс запускает OAuth через gateway `/oauth2/authorization/yandex`.
После подтверждения личности SSO проверяет привязку по Яндекс ID.
Активный привязанный пользователь входит без формы. Новому пользователю показывается форма завершения регистрации. Блок привязки существующего аккаунта в текущем интерфейсе скрыт.
Права ADMIN не выдаются до активации нового аккаунта администратором.

## Поля
Регистрация: username (6–100, латиница, цифры, точка, подчёркивание, дефис),
role (TRACKER/ADMIN, изначально не выбран), licenseAccepted, policyAccepted и consent (три отдельных обязательных согласия). Начальный @ удаляется автоматически на клиенте и сервере. Телефон не запрашивается.
Email и имя берутся только из ответа Яндекса, их нельзя подменить полями формы.
Привязка: username, password. Совпадение email не создаёт привязку автоматически.

## Текущие серверные маршруты
Это существующий контракт серверной HTML-формы, не готовый JSON API для SPA.
Все маршруты ниже обслуживает SSO, локально http://localhost:9000.
- GET /client/yandex/complete: HTML и серверная модель profile/error/fieldErrors/values.
- POST /client/yandex/register: application/x-www-form-urlencoded,
  username, role, licenseAccepted=true, policyAccepted=true, consent=true. После обработки — redirect на complete.
- POST /client/yandex/link: application/x-www-form-urlencoded, username, password.
  При успехе сервер продолжает исходный OAuth-вход; при ошибке — redirect на complete.
- GET /oauth2/authorization/yandex: повторное подтверждение у провайдера.

Оба POST требуют CSRF-токен и ту же сессию браузера. Thymeleaf добавляет CSRF
в форму автоматически. Пароль нельзя передавать в URL, журнал или аналитику.
Не переносить Яндекс access token или client secret во фронтенд.
Для отдельной React-страницы сначала согласовать JSON API и маршрутизацию с бэкендом;
текущий GET не следует вызывать как JSON endpoint.

## Состояния для дизайна
Загрузка; подтверждённая почта; ошибки заполнения; занятый аккаунт;
неверный логин/пароль; ожидание активации; блокировка; истёкшее подтверждение
(10 минут); превышение 5 попыток привязки за одно подтверждение;
отсутствие email от Яндекса. Ошибки не должны стирать несекретные заполненные поля.
После создания аккаунта — сообщение об ожидании активации, без автоматического входа.
Мобильный и настольный макеты, доступные подписи полей и клавиатурный фокус.

## Граница работ
До подключения окончательного интерфейса используется временная форма в стиле обычной регистрации TrackMe: фиолетовая карточка, светлые поля и белая кнопка. Соглашение размещено в прокручиваемом блоке. Кнопка заблокирована до заполнения всех обязательных полей, после отправки показывает загрузку. Сервер проверяет поля, каждое согласие и действительное подтверждение Яндекса. Текст соглашения взят из проекта без изменения содержания.
