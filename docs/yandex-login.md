# Регистрация и вход через Яндекс

Новый поток включается `YANDEX_LOGIN_ENABLED=true` одновременно у gateway и SSO. До включения сохраняется прежнее поведение. SSO должен получить `YANDEX_CLIENT_ID` и `YANDEX_CLIENT_SECRET` из секретов окружения. Значения секретов в репозиторий не добавляются.

В приложении Яндекс ID нужны разрешения `login:info` и `login:email`. Добавьте Redirect URI **точно** `<SSO_URI>/login/oauth2/code/yandex` (без завершающего слеша). Это публичный issuer SSO, а не адрес API gateway. Для localhost при `SSO_URI=http://localhost:9000` callback — `http://localhost:9000/login/oauth2/code/yandex`. Старый callback оставьте на время перехода. SSO должен иметь сетевой доступ к oauth.yandex.ru и login.yandex.ru.

Ссылка кнопки на основном сайте остаётся `/oauth2/authorization/yandex` у gateway. Gateway начинает OIDC-вход в SSO с подсказкой провайдера. SSO выполняет OAuth с Яндексом, затем выдаёт обычные токены TrackMe. Токен Яндекса не используется как токен API TrackMe.

Первое посещение показывает подтверждённую Яндексом почту и форму: имя пользователя Telegram, роль (TRACKER или ADMIN), принятие лицензионного соглашения и два отдельных согласия на обработку данных. Новый пользователь создаётся неактивным, как при обычной регистрации. После активации администратором повторный вход по Яндексу открывает тот же аккаунт. Новый пароль не требуется.

Отдельная форма привязки существующего аккаунта в текущем интерфейсе не отображается; серверный endpoint привязки сохранён. Совпадение email само по себе не связывает аккаунты. Роли и email существующего аккаунта не меняются. Неактивные и заблокированные аккаунты не могут авторизоваться или привязываться.

Liquibase добавляет nullable уникальный `sso.users.yandex_id`. Старые аккаунты сохраняются. Профиль для завершения регистрации хранится только в серверной сессии десять минут. POST-формы защищены CSRF, повторная привязка одного ID исключена ограничением БД.

## Проверка на стенде

1. Обновить SSO и gateway, применить миграцию; настроить перечисленные переменные и callback.
2. В приватном окне начать вход с кнопки Яндекса на основном сайте.
3. Зарегистрировать отдельный тестовый аккаунт с каждой ролью. До активации доступ должен быть закрыт.
4. Активировать аккаунт штатным способом и повторить вход. Проверить профиль и доступ к API от имени TrackMe-пользователя.
5. Выйти и войти повторно: форма регистрации не появляется, новый пользователь не создаётся.
6. Проверить привязку существующего аккаунта: неверный пароль отклоняется, верный сохраняет прежние права.
7. Проверить отказ Яндекса, отсутствие email, истечение формы, заблокированный аккаунт и POST без CSRF.

Настройки прод-сервера этой задачей не меняются. Полный OAuth-проход с реальным Яндекс ID требует проверки в браузере после настройки callback и секретов.

Для Docker-стенда с внутренним issuer `host.docker.internal` задайте у SSO `YANDEX_REDIRECT_URI=http://localhost:9000/login/oauth2/code/yandex`. Эта настройка меняет только callback Яндекса; браузерный адрес SSO и callback должны использовать один hostname, чтобы сохранялась сессионная cookie.

## Разделение репозиториев

Форма находится в track-me-frontend, маршрут `/yandex-registration`. В SSO нет HTML/CSS/JS формы.
После ответа Яндекса SSO перенаправляет незавершённую регистрацию на `${FRONTEND_URI}/yandex-registration`.
Укажите FRONTEND_URI без пути, с точным origin фронтенда (для локального nginx: http://localhost).

Публичный GET gateway `/oauth2/yandex/config` возвращает `ssoUri`: origin YANDEX_REDIRECT_URI, если он задан, иначе SSO_URI.
Для локального стенда с внутренним SSO_URI задайте YANDEX_REDIRECT_URI=http://localhost:9000/login/oauth2/code/yandex
также у gateway. В рабочем окружении оба сервиса должны видеть публичный callback SSO.
GET SSO `/client/yandex/profile` возвращает pending, email, csrfToken, csrfHeader и message.
POST SSO `/client/yandex/registration` принимает JSON: username, role, licenseAccepted, policyAccepted, consent.
Идентификатор Яндекса и email не принимаются из JSON: берутся исключительно из сессии SSO.
Запросы выполняются с credentials=include; POST требует CSRF заголовок из profile.
Успех: 201 с registered=true и сообщением об активации; ошибки: 400 с fieldErrors или message.
CORS разрешён только точному FRONTEND_URI, cookie SSO не передаются через gateway.
Выкладывать нужно оба ПР: фронтенд с новым маршрутом, затем SSO и gateway с новым API.
