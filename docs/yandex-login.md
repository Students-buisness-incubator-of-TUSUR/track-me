# Регистрация и вход через Яндекс

Новый поток включается `YANDEX_LOGIN_ENABLED=true` одновременно у gateway и SSO. До включения сохраняется прежнее поведение. SSO должен получить `YANDEX_CLIENT_ID` и `YANDEX_CLIENT_SECRET` из секретов окружения. Значения секретов в репозиторий не добавляются.

В приложении Яндекс ID нужны разрешения `login:info` и `login:email`. Добавьте Redirect URI **точно** `<SSO_URI>/login/oauth2/code/yandex` (без завершающего слеша). Это публичный issuer SSO, а не адрес API gateway. Для localhost при `SSO_URI=http://localhost:9000` callback — `http://localhost:9000/login/oauth2/code/yandex`. Старый callback оставьте на время перехода. SSO должен иметь сетевой доступ к oauth.yandex.ru и login.yandex.ru.

Ссылка кнопки на основном сайте остаётся `/oauth2/authorization/yandex` у gateway. Gateway начинает OIDC-вход в SSO с подсказкой провайдера. SSO выполняет OAuth с Яндексом, затем выдаёт обычные токены TrackMe. Токен Яндекса не используется как токен API TrackMe.

Первое посещение показывает подтверждённую Яндексом почту и форму: логин, телефон, роль (TRACKER или ADMIN), согласие с пользовательским соглашением. Новый пользователь создаётся неактивным, как при обычной регистрации. После активации администратором повторный вход по Яндексу открывает тот же аккаунт. Новый пароль не требуется.

Если аккаунт уже существует, пользователь подтверждает его логин и пароль в форме привязки. Совпадение email само по себе не связывает аккаунты. Роли и email существующего аккаунта не меняются. Неактивные и заблокированные аккаунты не могут авторизоваться или привязываться.

Liquibase добавляет nullable уникальный `sso.users.yandex_id`. Старые аккаунты сохраняются. Профиль для завершения регистрации хранится только в серверной сессии десять минут. POST-формы защищены CSRF, повторная привязка одного ID исключена ограничением БД.

## Проверка на стенде

1. Обновить SSO и gateway, применить миграцию; настроить перечисленные переменные и callback.
2. В приватном окне начать вход с кнопки Яндекса на основном сайте.
3. Зарегистрировать отдельный тестовый аккаунт с каждой ролью. До активации доступ должен быть закрыт.
4. Активировать аккаунт штатным способом и повторить вход. Проверить профиль и доступ к API от имени TrackMe-пользователя.
5. Выйти и войти повторно: форма регистрации не появляется, новый пользователь не создаётся.
6. Проверить привязку существующего аккаунта: неверный пароль отклоняется, верный сохраняет прежние права.
7. Проверить отказ Яндекса, отсутствие email, истечение формы, заблокированный аккаунт и POST без CSRF.

Настройки прод-сервера этой задачей не меняются. Полный OAuth-проход с реальным Яндекс ID требует проверки в браузере после настройки callback и секретов.
